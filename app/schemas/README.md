# Room schema history

This folder contains JSON files generated by Room during the build.

Example:

`app/schemas/com.dvid.dcam.platform.database.AppDatabase/1.json`

That file means: "when the app database is at version 1, this is the table
shape Room expects."

## What these files are

- A saved snapshot of the database structure for one Room database version.
- Useful documentation for reviewing database changes.
- Input for migration tests, so tests can check that an old database migrates
  to the exact expected new shape.

## What these files are not

- They are not runtime app logic.
- The app on a user's device does not read these JSON files.
- Missing JSON does not directly make the app crash.

Runtime behavior comes from:

- `AppDatabase.java`: the current entity and DAO manifest.
- `AppDatabaseMigrations.java`: the version number and `Migration(from, to)`
  objects.

## Fresh install vs existing install

Fresh install:

Room creates the latest database directly from the `@Entity` classes listed in
`AppDatabase.java`.

Existing install:

Room sees the old database version on the device and runs the registered
`Migration(from, to)` objects until the database reaches the latest version.

If an existing user has database version 1 and the app now uses version 2, Room
needs a valid `Migration(1, 2)`. If that migration is missing or produces the
wrong table shape, opening the database can fail at runtime.

The JSON file does not perform the migration. It only lets development tests
prove that the migration result is correct.

## Why commit the JSON

Commit schema JSON files with the database change that generated them.

Without the JSON, the app can still run, but future migration tests have no
saved expected schema to compare against. That makes it harder to prove a
migration is correct before shipping.

For example, a migration test can:

1. Create a fake old version-1 database.
2. Run `Migration(1, 2)`.
3. Ask Room to validate that the result matches `2.json`.

That test runs on a developer machine or in CI. It does not run on the user's
device.

## Adding the next version

1. Add the new version constant and migration in `AppDatabaseMigrations.java`.
2. Set `LATEST_VERSION` to the new version number.
3. Update the Room entity/DAO.
4. Build the app so Room exports the new JSON snapshot into this directory.
5. Commit the Java migration, entity changes, and schema JSON together.
6. Add or update migration tests when practical.

Before a database version ships, schema edits may be folded into that baseline
and its JSON regenerated. Never renumber, edit, or remove a released migration.
Add a new version that corrects it.
